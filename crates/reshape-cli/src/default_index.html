001 — Local render surface

LLM 动态生成 HTML，由浏览器即时渲染

Reshape 把自然语言请求转成 workspace 里的文件变更，再通过本地 7331 静态服务呈现结果。这里是默认画布；当 agent 写入新的 index.html，它会让位给真实产物。

localhost:7331 single session HTML / CSS / JS 
user request
  -> LLM tool loop
  -> workspace/index.html
  -> local static server
  -> browser render

项目的核心模型

Reshape 不是把界面藏在后端状态里，而是把页面当作可以被模型直接编辑的文件。HTML、CSS、JavaScript 都落在同一个 workspace 中，浏览器只负责忠实呈现这些文件当前的样子。

这让每一次生成都保持可检查、可回滚、可继续修改。agent 不需要猜测页面状态；它读取文件、写入文件，然后由本地浏览器验证结果。

Workspace 是源，浏览器是反馈面，LLM 是持续改写这个界面的操作者。 — Reshape runtime contract

一次生成如何发生

  1. 输入变成一个本地 turn
    本地 WebSocket 入口把用户意图标准化为协议事件，交给固定的 local session。
  2. 模型选择文件工具
    LLM 在预算限制内读取、写入、列出或删除 workspace 文件，直到页面足以完成当前任务。
  3. 静态服务暴露结果
    7331 端口从 workspace 根目录提供资源，根路径默认映射到 index.html。
  4. 浏览器成为真实渲染器
    生成结果不是截图或模拟预览，而是在本地浏览器中运行的页面。

默认首页的边界

这个页面只在 workspace 下没有 index.html 时自动生成。它的职责是让启动后的浏览器有一个清晰的第一屏，同时说明当前服务的渲染对象。

一旦 agent 根据请求创建页面，新的 index.html 会成为事实来源。Reshape 不会用默认首页覆盖已有文件，因为已有文件可能就是用户或模型正在工作的界面。

本地静态首页是空 workspace 的起点，不是最终产品界面。真正的页面由后续 LLM turn 写入 workspace。
